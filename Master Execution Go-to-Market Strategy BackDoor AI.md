## SECTION 1: EXECUTIVE SUMMARY & PRODUCT VISION

### Mission Statement

BackDoor AI exists to eliminate performance asymmetry in high-stakes job interviews. The traditional interview format favors performative rhetoric, rote memorization, and artificial confidence over genuine capability, problem-solving depth, and on-the-job competence.

By serving as an unobtrusive, real-time background intelligence layer, BackDoor AI bridges the cognitive gap caused by interview anxiety, memory blanks, and high-pressure stress. The mission is to level the hiring playing field, ensuring capable candidates present their true potential and secure the compensation and roles they deserve.

### Core Value Proposition

BackDoor AI is a covert cognitive copilot engineered for live conversational support. Unlike static interview preparation tools, cheat sheets, or practice bots, BackDoor AI operates dynamically in the background during live meetings. It intercepts incoming conversational audio and screen context, runs instant semantic extraction, and delivers structured, contextually precise talking points, code frameworks, and behavioral answers within milliseconds. It functions as an invisible second brain, providing:

* **Sub-Second Low-Latency Retrieval:** Near-instantaneous transcription and inference designed to feed answers within natural speech pauses.
* **Invisible Heads-Up Interface:** Ultra-minimalist, semi-transparent UI engineered to sit directly beneath a webcam line-of-sight to preserve natural eye contact.
* **Domain-Adaptive Intelligence:** Contextual switching tuned across technical systems design, live coding algorithms, corporate finance models, and structured behavioral rubrics (STAR method).

## SECTION 4: TECHNICAL & LEGAL FRAMEWORK

### Architecture & Privacy Guardrails

```
+-----------------------------------------------------------------------+
|                       ZERO-KNOWLEDGE ARCHITECTURE                     |
|                                                                       |
|  [Local Virtual Loopback Audio]                                       |
|             |                                                         |
|             v                                                         |
|  [Client-Side Ephemeral Chunking] (100ms In-Memory Buffers)           |
|             |                                                         |
|             v (TLS 1.3 Streaming WebSocket)                           |
|  [Inference Proxy Server] (Zero-Log Gateway)                          |
|             |                                                         |
|             v                                                         |
|  [High-Performance LLM / RAG Engine]                                 |
|             |                                                         |
|             v (Encrypted Token Return)                                |
|  [Client Display Layer (RAM-Only Rendering)]                          |
+-----------------------------------------------------------------------+

```

* **Ephemeral In-Memory Processing:** Incoming microphone audio and desktop system audio are captured via local virtual loopback drivers and processed in 100-millisecond in-memory audio buffers. Audio data is discarded immediately following transcription tokenization.
* **Zero Disk Persistence:** No raw audio recordings, screen capture frames, or generated textual transcripts are ever written to non-volatile disk storage on client devices or remote servers.
* **Encrypted In-Transit Pipelines:** All communication between the client overlay application and LLM inference endpoints runs over TLS 1.3 streaming WebSockets with end-to-end payload encryption.
* **No-Training Guarantee:** Strict enterprise-grade API agreements with foundational model providers ensure user payloads are explicitly excluded from model training datasets.
